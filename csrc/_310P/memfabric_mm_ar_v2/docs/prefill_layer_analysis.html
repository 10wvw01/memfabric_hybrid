一、数据来源与测量口径

数据批次：A1-R1（2026-10-27，最新一轮实机取证）。逐站点切片取自 evidence/a1_r1_batch_20261027/s4_l2/（20 份 JSON：未融合/融合 × rank0/rank1 × 5 步）； 全模型算子分解直接解析本机服务器全量 kernel_details.csv（/tmp/opencode/a1-batch/l2/l2_stock/…，17 258 个 kernel、5 个完整 prefill 步）。
口径：Qwen3.6-35B-A3B-w8a8，input 4096 / output 1，TP2（单卡双 Die），Eager，M=4096、K=N=2048，rank0。 每步设备忙时 2 350.2 ms ≈ 墙钟 2 344.7 ms（重叠系数 1.00，近似串行，求和即近似真实）；占比以设备忙时为分母。 融合版第 0 步含 70.6 ms 双 Rank 同步离群（已保留在证据中），融合合计取后 4 步平均。

二、模型结构速览与单层数据流

模型共 40 层：10 个全注意力层（full_attention）+ 30 个 GDN 线性注意力层（gated delta net），每层都挂 MoE（W8A8 量化专家）。后面的排名表和构成图都以这里为"词汇表"：

RmsNorm → [全注意力: QKV投影 → FlashAttention   /   GDN: Conv → Sigmoid门 → WY → FwdH → FwdO]
        → o_proj / out_proj 矩阵乘          ← 融合替换目标（40 处）
        → 跨卡 AllReduce                    ← 融合替换目标（40 处目标位置 + 41 处其他）
        → RmsNorm → MoE路由(TopK) → 专家分组矩阵乘 + SwiGlu → 还原合并 → 残差相加

八、结论

① 时间大头在 MoE 与 GDN：MoE 专家计算占 45.3%（单算子最大 27.7%）、GDN 线性注意力占 24.7%；FlashAttention 仅 3.7%（只有 10 层）。
② 融合目标占比有限：40 个 o_proj/out_proj 矩阵乘 + 目标位置跨卡求和合计约 90.5 ms、3.9%，其中矩阵乘仅 1.3%——即使全部优化到零，整步理论上限也只快约 4%。这是"单算子赢了但模型没变快"的定量根源，也是 L3/L4 逐级验收存在的原因。
③ 当前融合版更慢：每步比未融合多约 14 ms（rank1 约 20 ms），与 L3 实测整步慢 26–28 ms 方向一致（差额来自计时口径与并行重叠）。
④ 优化主战场：每层忙时均匀（48–64 ms），MoE 在每层都是最大成分；若目标是整步/TTFT，主战场是 MoE 专家矩阵乘与 GDN 核，而非融合目标站点。

九、边界与数据说明

① 层段以每层 o_proj/out_proj 站点为锚，起点比真实层边界略有偏移；② 全部 kernel 时长按流求和，本负载重叠系数 1.00（近似串行），求和近似真实；③ rank0/rank1 设备时钟未校准，本页仅呈现 rank0，两卡数据各自独立统计、不相减；④ 融合版第 0 步的 70.6 ms 双 Rank 同步尖峰（layer 10）保留在证据中未剔除，融合合计取后 4 步平均；⑤ 次数与层归属由整除关系印证，个别 MatMulV2 层内细分为合理推断。
