# 12｜术语表：小白版，而且告诉你最容易混淆什么

> 建议不要一次背完。读其他章节遇到术语时回来查。

---

## ABI

Application Binary Interface。人话：两个编译后模块约定“函数怎么叫、参数怎么排、结构体长什么样”。

本项目里 adapter ABI 用来隔离 vLLM MM+AR runtime 和 MemFabric 实现。

易混：API 更偏源码调用约定；ABI 还涉及二进制布局与兼容性。

## ACL Graph

把一串设备操作 capture 后重复 replay，主要减少 host launch 固定成本。

不是“自动让 kernel 算得更快”。它反而会约束地址、资源初始化和生命周期。

## AI Core

310P 上执行矩阵/向量计算的计算核心。当前大 M MM+AR 使用 8 个 AI Core 协作。

## AllReduce

多个 rank 都有 partial，最终每个 rank 得到 reduction 结果。

TP=2 当前目标语义：

```text
Y = Y0 + Y1
```

## arena

预先分配并重复使用的一片通信/结果内存。不是每个 batch 临时 malloc。

## baseM

当前协议的基础行粒度：256。

## batch

本项目语境里可能有三种意思：请求 batch、Scheduler 本轮 batch、MM+AR `batch_m`。必须看上下文。

## batch_m / q

```text
batch_m = baseM * q
q ∈ {1,2,4}
```

q 控制单次生产/通信粒度，不是“并发请求数”。

## block table

把逻辑 KV block 映射到物理 KV block 的表。

## cache clean

让 AI Core 写出的数据对后续 SDMA 等消费者可见所需的一致性动作。

不是“清空 tensor”。

## continuous batching

vLLM 动态把不同请求当前可执行的 token 拼到同一轮 forward。

所以用户并发数不等于某个 Linear 的 M。

## credit

资源复用许可证。当前 wave credit 主要防止下一 wave 覆盖 peer 仍在使用的 arena。

## custom op

框架注册的自定义算子入口。Python 看起来像普通 op，底层可以进入 C++/AscendC。

## Decode

已有 KV Cache 后，继续生成新 token 的阶段。通常 M 比 Prefill 小得多。

## DFlash

本项目使用的 speculative decoding 路径之一。核心是用 drafter 先提候选，再由 target 一次 verify 多个 token。

## eager

普通逐次执行模式，与 Graph capture/replay 相对。

## EP

Expert Parallel。MoE expert 跨设备分布的并行方式，与 TP 不是一回事。

## FP16

16-bit floating point。本次目标 o_proj/out_proj MM+AR 当前使用 FP16 数据合同。

## GDN

Qwen3.6 linear attention 路径中的 recurrent/linear attention 相关结构；其输出也有 `out_proj`。

## generation

ready cell 中写入的代际标签，用来区分“这一次完成”和旧 wave 留下的完成状态。

不是文本生成 token 的 generation。

## GM

Global Memory，可粗略理解为设备侧主存可见空间。

## hidden state

Transformer 内部 token 表示。shape 常见 `[M, hidden_size]`。

## INT8 / W8A8

W8A8 表示权重/激活整体量化方案，但不代表模型里每个 Linear 都一定走 INT8。本次目标 projection 被 skip，当前融合走 FP16。

## ITL

Inter-Token Latency，连续输出 token 之间的延迟，是 Decode 体验的重要指标。

## K

最容易混淆的字母之一：

- GEMM 的 K：内积维度；
- speculative 的 K：draft token 个数。

必须看上下文。

## KV Cache

缓存历史 attention 的 Key/Value，避免每次 Decode 重算全部历史。

## lookahead

流水中允许提前 enqueue 后续 producer 的深度。当前设计使用 lookahead=1 思路。

它是性能策略，不是数学常数。

## M / N / K（GEMM）

```text
A[M,K] @ B[K,N] = C[M,N]
```

当前 MM+AR 本地：

```text
K=2048
N=2048
M 动态
```

## MemFabric

本项目用于 310P rank 间共享内存/SDMA 通信协同的外部能力。vLLM 通过 adapter/public API 使用，不依赖私有内部结构。

## MoE

Mixture of Experts。token 路由到少量 expert 计算，常带来 dispatch/combine 和负载均衡问题。

## mRoPE

多维 Rotary Position Embedding 相关 position 处理。spec decode 需要正确维护对应位置元数据。

## M-split

多个 core 按输出行 M 分工。当前大 M path 使用。

## N-split

多个 core 按输出列 N 分工。当前 small-M path 使用，减少每核 weight working set。

## NZ

Ascend 侧适合 Matmul 的一种物理数据布局。数学矩阵不变，内存排布改变。

## o_proj

Attention 输出投影 Linear。本项目 full attention 的融合节点。

## out_proj

linear attention/GDN 对应输出投影。本项目另一融合节点。

## patch

对通用执行路径做定点替换/接管。310P 当前通过 worker patch 等方式接入特化逻辑。

## Prefill

处理已有 prompt 的阶段，通常一次处理很多 token，M 往往较大。

## producer

MM+AR 里产生本地 partial 并在可通信后 signal 的阶段。

## proposer / drafter

Speculative decoding 中提出候选 token 的角色。

## quiet

等待/确认当前相关异步通信不再 in-flight 的收尾语义。

不是每个 batch 都应该无脑调用，否则可能破坏 overlap。

## rank

分布式并行里的一个参与者。TP=2 有 rank0/rank1。

## ready

卡内多 AI Core 的完成标志。当前是 generation-tagged ready cell。

它不是跨卡通知。

## reduce / reduction

把多个 partial 按某种操作合成一个结果。本项目是 SUM。

## reduce_results

RowParallelLinear 上层是否还要做 TP reduction。融合算子已完成 reduction 时必须关闭。

## SDMA

负责设备内/设备间数据搬运的 DMA 能力之一。本项目希望让 SDMA 与 AI Core MM 重叠。

## signal / wait

通信 producer/consumer 的同步原语：signal 宣布数据可搬/可见；wait 等待对应 peer 数据满足条件。

## slot mapping

逻辑 token 对应到 KV Cache 物理槽位的映射。DFlash 展开多个 token 后尤其关键。

## small-M

M 很小时的性能区间。此时 FLOPs 少，但固定开销和 weight streaming 可能占主导。

## speculative decoding

先用便宜路径猜 token，再用 target 批量验证，目标是减少 target Decode 轮数。

## stream

设备操作按顺序 enqueue 的执行流。host API 返回不代表设备已经完成。

## T stair

small-M path 把实际 M 映射到离散 T：

```text
{16,32,64,128,256}
```

用于减少动态 shape/内核变体。

## tail

M 不能整除 batch_m 时最后不足一整批的有效行。

## TP

Tensor Parallel。一个 Linear/Attention 的 tensor 维度被拆到多个 rank。

## TTFT

Time To First Token，从请求到首 token 的延迟。

## wait

本项目 wait 主要确认 peer 对应 batch 数据已到达并可使用，不等价于整个 wave quiet。

## wave

一组共享同一轮协议资源和 generation/credit 生命周期的 MM+AR batches。

## Worker / Runner

Worker 管设备/进程执行环境；Runner 更贴近一次 model execution 的输入准备、Graph 和 forward 调用。

---

# 最容易混淆的 8 组概念

```text
请求 batch       ≠ MM+AR batch
ready            ≠ signal
wait             ≠ quiet
W8A8 模型        ≠ 所有层 INT8
Graph 快         ≠ kernel FLOPs 变少
TP reduction     ≠ EP dispatch
Decode Split-K   ≠ MM+AR 8-core M-split
当前实测最快     ≠ 永久最优
```

最后一组尤其重要：性能术语永远要带 workload 和环境。
