# 已证实 / 推断 / 未证实（Gate E 507014 联合取证裁决基准）

> 本文件是交接包的裁决基准：双方（V2 侧与 MemFabric 侧）只依据此处列出的
> 证据与推导链讨论根因，不引入未列出的假设。
> 分级：**observed**＝日志/直采实值；**derived**＝由 observed 推出（推导链列出）；
> **unknown**＝无证据，禁止推测补全。

## 1. 已证实（observed，日志直录可复查）

1. **故障形态**：双 Worker 507014（AICore timeout，设备 plog 0x7150025/0x25），
   V2 8 核代际一致冻结（D1R4=1730），Core0 停 stage50（`wait_at` 未返回，
   非 52/53），Core1–7 停 stage60。
2. **被等槽旧值**：dev0 环槽 440 实读 stamp/mail=7609（期待 8633）；
   dev1 环槽 442 实读 7611（期待 8635）。Host DMA 直读显存与 AICore volatile
   轮询两条独立读路径同读旧值。
3. **读取路径正常**：同帧快照边界槽 1020–1023（8189–8192）、槽 0–2
   （8193–8195）均为本圈/上圈自洽值；dev1 环槽 440 曾正常落环 8633 并被
   消费返回（status=0）。
4. **控制面全绿**：停滞瞬间双侧 SQ 空（hwHead=hwTail，rc=0）、reqSeq 全消费、
   Epoch 干净轮转（exitReason 全 0）、编排 phase 8 空闲、snapshotError=0。
5. **V2 投递动作成功**：Core0 是唯一 signal owner；signal 返回 ok（失败会当场
   Trap，走不到 50）；请求环确有该件（后续被 AICPU 消费）。
6. **同型工况大量成功**：D1R1–R3 共 300 请求 0 失败（约 45k 件 AICPU 消费、
   44 次 1024 边界穿越）；C2R1 15027 件/设备；D2W1/W2/W4 窗口压力 768 调用
   零失败；丢失前同型 ARR 写入约 8632 次/方向连续成功。
7. **复现画像**：会话级复现率 G3 1/2 + G1-C 1/2 + G1-D 1/10 = 3/14 ≈ 21.4%；
   等待形态三例一致（即时完成或永久挂起，无慢等待）。

## 2. 推断（derived，推导链可复验）

1. **游标数学**：`wait_at` 源码（`smem_shm_aicore_base_sdma.h:156-176`）证明
   ArrHead 为消费游标 → 被等槽=440/442、期待单号=8633/8635、旧值差恰一圈
   （8633−7609=1024，8635−7611=1024）。
2. **单件丢失而非连续损坏**：dev1 环 seq 8633 正常返回后 ≤0.2s 下一件永不
   出现；dev0/dev1 同编号槽 440 一侧缺件一侧已消费。
3. **"仅 1023 边界丢写"假设关闭（双向反证）**：健康侧边界槽全对（D2-B 静默帧
   + D1R1–R3 静默帧）；故障侧被等槽 440/442 在环中部。
4. **因果链（强候选，尚未定案）**：按 V2"先 signal(k) 后 wait(k−1)"顺序，
   rank0 卡 wait(chunk0) → 永不到达 signal(chunk2) → rank1 的 wait(chunk2)
   属级联。**全案只需一起原发性丢失：rank1→rank0 的 chunk0 邮件
   （dev0 环槽 440，单号 8633）**。C2R2 同构（chunk1/chunk3）。
5. **丢失区间夹逼**：请求被投进环（signal ok）→ 环被消费干净（reqSeq 推到头）
   → 但对端柜子从未出现新单。丢失发生在**AICPU 消费请求之后、对端保留区
   写入落地之前**——该区间为 MemFabric 执行域（SQE 组装/提交 → CP/SDMA
   执行 → 写显存）。
6. **V2 侧已洗清（高置信）**：邮件校验逻辑（stage50 未执行校验且此前约 9000
   次同校验全过）、分块/流水编排、signal 调用、输出槽池管理（w4 失败另案：
   harness 残留引用触发保护性守卫，非通信缺陷）。
7. **"写入未落地"与"读不可见"的判别（V2 侧分析结论）**：Host DMA 与 AICore
   两条独立读路径同读旧值 → 若新单已写显存，Host DMA 必能读到 → 倾向判定
   **写入未落地**。⚠️ 总账口径提醒：该判别依赖"Host DMA 读时序上晚于 SQE
   应落地时刻"，最终定案仍需逐 SQE 硬件完成记录；在此之前按
   "MemFabric 投递/内存可见性接口异常"移交，不写"MemFabric 软件 BUG 实锤"。

## 3. 未证实（unknown，明确缺口，不得推测补全）

1. **逐 SQE 证据（本包最大缺口）**：丢失邮件对应的 3 条 SQE（数据拷贝 /
   写到达戳 / 写完成戳）各自的源/目的地址、长度、立即数、入队序号、提交时刻
   硬件 Head/Tail、完成/错误回执、最终读回——全部缺失。这是把根因从
   "某段路"定位到"哪一步"的唯一直接证据。
2. **错投槽位可能性**：440 号柜隔壁（441/442…）有没有被错投——区分
   "写入彻底丢失"与"写错槽位"。现有采样只覆盖被等槽与边界槽。
3. **根因层归属**：MemFabric Host 代码 / AICPU SQE 组装 / CP/SDMA 硬件执行 /
   缓存写回 / V2-MemFabric 并发与内存可见性约束未被满足——现有软件证据
   只能到"MemFabric 执行域"为止。
4. **双 Rank 对称表现是否同因**：两侧被等邮件均为各自环末封（8633 缺件 /
   8635 因级联不至）——C2R2 与 D1R4 是否同一机制尚无逐件映射证明。
5. **低概率自恢复**：无"近失/慢等待"样本，但样本量不足以排除。

## 5. 双方接口合同与验收基准

### 5.1 V2 侧（vllm-ascend）遵守的使用条件

- **调用顺序**：每 chunk 计算完成后 Core0（唯一 signal owner）先
  `signal_at(k)`，再 `wait_at(k−1)`；收尾 wait 最后一块。
- **缓存维护**：signal 前对本端数据 `DataCacheCleanAndInvalid`；MM 后本端
  CleanLines；对端 Add 前 CleanLines（协议 `MM → clean → ready → signal →
  peer wait → add`）。
- **生命周期**：输出槽 4 个循环复用 + 新地址首写设备级同步；arena 槽位由
  runtime 管理；Graph 生命周期与 eager 分离。
- **背压/完成**：credit 保护接收环不溢出；`quiet` 放 wave 尾批量确认；
  DONE 握手收尾；满环时 signal 自旋背压。
- **允许并发条件**：单 Writer（Core0）写请求环；TP2 双向同时收发；
  1Hz Host 采样仅读不写。

### 5.2 MemFabric 侧接口合同（本次待裁决的实现域）

- `signal_at`：请求 4 字段写请求环 → 刷缓存 → 推进 REQ_TAIL。
- `wait_at`：轮询 `ARR_STAMP[ArrHead%1024] == ArrHead+1`，取件后推进 ArrHead。
- AICPU 编排：每请求生成 **3 条 SQE**（数据拷贝 → 写对端到达戳 → 写本端
  完成戳）并提交 CP SQ（深度 1024）；到达环 1024 槽。
- 涉及源码：`src/smem/include/device/smem_shm_sdma_layout.h`（布局）、
  `src/hybm/ops/hybm_kernel/hybm_sdma_orch_kernel.cc`（编排/SQE）、
  `src/smem/include/device/smem_shm_aicore_base_sdma.h`（原语）。

### 5.3 修复后验收（"根因已解决"的最低门槛）

1. 单变量修复 + 可复现案例证明因果（问题随改动消失并能解释原因）。
2. 无诊断埋点二进制：T0/T1/T2、位精确、混合路由、冷启动全矩阵回归。
3. 多轮 Gate E 长稳（≥历史复现率换算的置信轮数）+ 双 Rank 异步连续压力。
4. 端到端性能终验（真实吞吐/TTFT/TPOT/尾延迟）不得因修复回退。
5. "修复后一次没再遇到"不算根治；必须能解释原来为什么坏、修了哪里。

## 6. 下一轮最小联合取证建议（总账 §5.4 分工）

1. **V2 侧**：把 D1R4 的 rank/代际/期待 seq/chunk/来源 signal 与接收槽一一
   对应成表；复核 V2 使用条件是否全部满足 MemFabric 接口合同。
2. **MemFabric 侧（本包主要请求）**：为目标请求增加低开销、可关闭的
   **3 SQE 组装/入队/执行完成逐单证据**；核对写 stamp/mail 的顺序、目的地址、
   缓存与可见性；**先取证后改代码，不先动协议**。
3. **现场（OpenCode @ 310P3）**：单独 G1 取证环境短窗复现；出现 507014 立即
   停止保全 plog/manifest/原始 trace，不自动重启。
4. **证据会合后**：裁决"SQE 未组对/未送出 / 硬件未完成或写错目标 /
   落地但接收看不见 / V2 使用条件不满足"，再决定由谁修哪一行代码。
