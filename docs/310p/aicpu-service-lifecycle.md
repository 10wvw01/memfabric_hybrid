# 310P AICPU传输服务生命周期

MF在host进程内持有独立服务Context。服务Context中的AICPU任务消费请求、提交SDMA；业务Context继续运行应用任务。业务同步只等待业务Context内的任务，NBI操作仍需quiet确认完成后才能复用缓冲区。

## 配置

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| MF_SDMA_ORCH_MODE | resident | resident持续运行；正整数表示有限轮次的秒数，范围1～4294967294 |
| MF_SDMA_ORCH_HOST_LEASE_MS | 10000 | host健康序号不变的最长时间，最小3000毫秒 |
| MF_SDMA_ORCH_STOP_TIMEOUT_MS | 5000 | 服务停止和排空预算，最小1000毫秒 |

模式由MF_SDMA_ORCH_MODE统一选择，未设置或值为空时默认常驻。设置resident表示常驻，设置15表示每轮运行15秒；0、负数、epoch及其他非法值会导致初始化失败。host每秒更新健康序号，设备通过单调时间判断失联。长时间暂停整个host进程也会触发失联。

    export MF_SDMA_ORCH_MODE=resident

有限轮次示例：

    export MF_SDMA_ORCH_MODE=15


## 停止和释放

服务状态为STARTING、RUNNING、DRAINING、STOPPED或FAILED。请求tail发布表示请求已接受。停止时关闭新提交，等待正在发布的生产者退出，处理已接受请求，并通过最后完成戳确认SDMA结束，随后确认服务stream完成。

多rank正常关闭前，应用协调各rank停止新通信，完成quiet及业务stream同步，再通过已有同步接口协调销毁。销毁成功后才释放相关缓冲。

host失联和传输错误会停止新请求。完成情况不确定的ADD不会自动重放。时钟失败、HAL错误和等待超时都会报告明确错误。HAL调用自身不返回时，由host有限等待返回失败，保留仍被引用的资源。

smem_shm_sdma_get_status返回维护线程发布的服务状态快照，服务失败后仍可查询。状态更新通常间隔100毫秒；host暂停时快照停止更新，恢复后再读取设备终态。错误1380表示host失联，1383表示host停止等待超时，1384表示维护线程失败，1385表示SDMA完成状态连续1秒没有推进。

smem_shm_destroy失败时句柄继续保留，应用停止使用该池并保留可能被SDMA引用的缓冲区。全局反初始化、实体工厂和初始化回滚均遵守资源确认；库不自动重置设备。进程强杀后的最终映射回收依赖CANN与驱动。

## 协议与回退

Host库、AICPU SO及AICore头文件需配套更新。Host/AICPU握手校验协议和本次启动标识；使用新头文件重新编译AICore kernel。请求环、完成戳及暂存槽原有偏移保持不变，新增控制字段使用保留区空闲范围。工作区的host停止标志和健康序号与AICPU诊断分占缓存行，避免缓存写回覆盖对方更新。

切换为每轮15秒的有限轮次时，设置MF_SDMA_ORCH_MODE=15。有限轮次同样启用租约和资源释放保护。故障资源得到确认或由外部平台恢复后再创建新实例。

诊断记录包含设备号、服务实例、错误码、资源确认及最后SQ状态。记录源码提交、实际加载SO摘要和运行配置，可将故障对应到具体产物。设备管理查询使用有限等待，查询失败后保存原始日志并由平台处理。
