# 310P（Atlas 300I Duo / Ascend310P3）平台事实档案

> **文档定位**：长寿命技术档案（10 年生命周期）。F1-F20 提炼自《310p-2rank-vmm-开发计划.md》
> 第一节（VMM 池化工作，2026-09 实机验收），协同模式实测事实为历轮实机验证沉淀。
> 全部条目经本机（4 卡 × 2 die，dev0↔dev1）实测。
>
> **读者**：在 310P3 上做适配、排查驱动/工具链差异、或评估平台能力的开发者。
> **注意**：这些是**本机实测定论**，驱动/CANN 版本变化可能改变结论，跨环境使用前
> 应复核关键条目。

## 2. 行为差异与坑（F16-F20：适配中发现）

| # | 事实 | 证据 |
|---|------|------|
| F16 | 310P **不支持 SDID/SERVER_ID/SUPER_POD_ID 查询**（rtGetDeviceInfo 返回 207000）——已做容忍降级（310P 降级为无效值+WARN，可达性改由段映射状态判定） | e2e 实测（V2 改进：改用公开 API `aclrtGetDeviceInfo`） |
| F17 | join 重试会**重复 import 同一 shareableHandle** → 107017——Import 需幂等去重（按 rankId+sliceIndex） | e2e 实测（strace+日志定位） |
| F18 | 本地池地址分类依赖 reservedMap（AclVmm 段不登记）——`ClassifyAddressMask` 扩展：allocatedMap 命中且非 imported → LOCAL\|GLOBAL 双位 | e2e 实测（对 910B 行为等价） |
| F19 | **join 为动态成员语义**：先 join 的 rank 单成员即返回 OK，peer 映射在对端 join 完成后才就绪——使用方需在全员 join 后同步再拷贝（Barrier 模式即正确姿势） | e2e 实测（使用方契约） |
| F20 | `ReleaseSliceMemory` 存在 use-after-free（ASAN 独有检出，手工链接非 ASAN 版漏检）——已修复 | 正式 UT 二进制（ASAN+gcov）实测 |

## 3. 协同模式关键实测事实（机制细节见机制档案）

| 事实 | 出处 |
|---|---|
| SMMU 可译 AclVmm 池 GVA（含导入映射）——数据 SQE 的 src/dst 直接用池地址成立，Plan B（段层 IPC 导入）不启动 | E0b 轮A/轮B 双 PASS，数据全对 |
| **AICore 可直接 GM 访问池 GVA**（写 pattern / 读改写 INC / dcci 轮询池内标志全通）——SHM 设备发起语义的基石 | E0c 实测 |
| 两侧 AICPU 同构 role0 成立（通知上移 AICore 直接 dcci 池内标志） | E0c 实测 |
| die0 ssid=2 / die1 ssid=5（SMMU 子流按 die 区分，实时查询值） | E0c 实测 |
| **CP1 部署链（实测）**：每卡独立设备 OS 文件系统（dev2 看不到 dev0 部署的文件，`/usr/lib64/aicpu_kernels/0/` 路径各卡同名，die 对共享）；mode=0 加载**不校验**设备文件存在（dlopen 惰性到 launch，须显式探测）；CUST 迁移文件名**不含 host pid** 且 getfunc 返回值不可靠（正确入口名也 107000 但文件照样落盘）；KFC 设备 shell 工具箱极简——`stat/wc>重定向/md5sum/cksum/cmp` 缺失，`grep/awk/ls -l/顶层管道` 可用，`$()` 仅简单形式可用（文件校验用 `ls -l \| awk '{print $5}' \| grep -qx <size>`）；json 加载器要求 `.json` 扩展名（无扩展名 107000）；`cat $(可能为空)` 会退化为 stdin 等待挂死（须裸 glob 快速失败） | 本轮自动部署实机调测（KFC 布尔探针矩阵） |
| **【勘正 2026-09-18】"AICore 读 meta 恒为零"结论有误**——真因有二且均已在库内修复：① meta 区 AclVmm 映射缺 `AclrtMemSetAccess` 设备授权（池段有此步故 AICore 可读，`Hybm310PInitMetaGva` 遗漏）；② 设备头 `__gm__ void**` 解引用型 getter 在 dav-2002 后端读取错误。修复后 rank/rankSize/symmetricSize/工作区槽 kernel 内全部读对（EX_META 探针双 rank PASS） | P0a 实验实测（D2H 回读对照 + 四路判别探针） |
| **AICPU watchdog ~30s（实证 2026-09-18）**：硬杀非终止 kernel（58×500ms≈29s 击杀、无完成标记、sync 返回 507901）；launch attr TIMEOUT **不是**设备杀（25s attr 下 kernel 活到 30s 才被杀，属 host 同步语义）；有界运行干净完成（20s：精确 40 拍+完成魔数+sync=0）；击杀后共享调度器可恢复（KFC 通道活性正常）——长驻消费须用自限 epoch+host 监督立即续命实现（**勘正 2026-09-21**：①epoch 预算按实测节拍 ~130µs/循环计价而非退避时长——旧 220000×100µs=22s 假设致实跑 28.6s 必被杀、自退永不可达；②**epoch 超时击杀终局为 hdc 断链**（`Hdc socket close`/`DEV_RUNNING_DOWN`/sync 507901）——本机实测击杀边界 35.9s（attr=60 惰性下同值，即设备侧 watchdog 口径；板间漂移 28~36s），**进程级永久不可恢复**（90s launch 探针零恢复，"击杀后可恢复"仅对 KFC 通道成立、对 kernel launch 不成立）——结论：epoch 必须自限于一切击杀边界之前，续命只能靠"从未被杀"；③空闲节拍即有 116→140µs/循环漂移，循环数预算本质不可靠，epoch 改墙钟自限 cntvct_el0 18s（纪内差值 + usleep 下界标定频率，节拍漂移免疫）；④launch cfg 空属性（numAttrs=0）被 runtime 拒绝（107000 invalid value），attr 仅作 API 占位且取值须大于击杀边界；⑤watchdog 击杀健康纪不计放弃计数直接续命（纵深防御，若未来固件击杀可恢复则生效） | wd_probe 心跳探针三连实测（A: attr25/120s 被杀；B: attr60/50s 仍 30s 被杀；C: attr60/20s 干净完成）+ 2026-09-21 ex08v 五相实机复测（v7 浸泡 t=120s 死亡复现/vt1+vt2 边界 35.9s 双确认/launch 90s 零恢复/v9 空闲 11min+满载 62s 全绿） |
| **CUST 迁移 json 基名配对**：加载器要求 json 文件基名与 .so 同名（异名 load 107000，json 内容与 .so 逐字节一致仍复现）；部署时 json 命名须为 `<soname>.json` | wd_probe 部署链二分实测（同名即通/异名即败） |
| **bisheng dav-2002 工具链约束（910B 后端无此限制）**：运行时整数→`__gm__` 指针 cast 会错位——`(__gm__ void*)` 型恒 +0x2000（-O0/-O2 均错）、变量绑定型 u64 cast 在 -O2 错位（-O0 正常）、经该指针写读错位；而编译期常量地址的标量立即解引用、kernel 参数传递的指针、指针算术均正常。**设计纪律：kernel 内勿物化整数 cast 出的指针（变量绑定/下标恒偏）；`*(volatile __gm__ T*)(运行时整数)` 的立即解引用（T1 实测）与 kernel 参数指针算术可用——V5 设备头全部建立在两者之上**（910B rdma 代码的 `SetGlobalBuffer((__gm__ uint32_t*)runtimeAddr)` 同款模式在 310P 不可用） | EX_META 探针 A/B/C 三路判别（-O0/-O2 对照）实测 |
| 流水加速比实测（8×128KB）：8.02x→7.87x（文件会合口径，实为 100ms 尾睡摊薄假象）→ **2.0~2.3x（V3 kernel 修复尾睡后诚实口径）** | 08 示例历轮实测，V3 kernel 修复尾睡后重测 |
| 310P 的 AICore（dav-2002）**不能投 STARS SQE**（无该路径）——协同模式用 AICPU 代投 | 迁移动机，历史实测 |

## 4. 工具链差异笔记（bisheng / hcc / dav-2002）

| # | 坑 | 正解 |
|---|---|---|
| T1 | AICore kernel 编译：AIV_ONLY 被拒 | `--npu-arch=dav-2002` + `KERNEL_TYPE_AICORE` |
| T2 | bisheng 的 `-x asc` 会把后续 `.a` 也当源码 | 显式 `-x none` 切回 |
| T3 | clang/lld 链接缺数学库 | 显式 `-lm` |
| T4 | AICore kernel 内**不支持 lambda** | 辅助函数用文件级 `__aicore__ __inline__` |
| T5 | `__gm__` 限定只出现在 kernel 形参 | host 调用侧用普通指针；`static_cast<__gm__ T*>` 报 "casts away qualifiers" |
| T6 | AICore 侧无可用 cycle 计数器 | 等待段用 dcci 迭代数近似；AICPU 侧 `cntvct_el0`（机制档案定论 7） |
| T7 | bash 陷阱：`export X && cmd0 & cmd1 &` 中 `&` 优先级使 export 只作用于第一个后台子 shell | 双进程脚本显式在子命令内 export 或用 `env` 前缀 |
| T8 | 新增源文件后 CMake GLOB 不自动收编 | 重新 `cmake -B build` configure 再 build，否则链接旧档案报 undefined reference |

## 术语注释表

| 术语 | 说明 |
|---|---|
| die 对 | 同卡的两个芯片逻辑单元（dev0/dev1 共享设备 OS 文件系统） |
| AclVmm | CANN 虚拟内存管理接口族（ReserveMemAddress/MallocPhysical/MapMem/Export/Import） |
| shareableHandle | VMM 导出的跨进程共享句柄，对端经 Import 建立映射 |
| GVA / 对称基址 | 全局虚拟地址；各 rank 的 GVA 起始地址一致（F11），互访纯算术 |
| SMMU ssid | 子流标识，SDMA 搬运时按 streamid+ssid 翻译地址 |
| STARS SQE | A3 上 AICore 可直投的 SQE 路径；310P AICore 无此路径（第 3 节末行） |
| dav-2002 | 310P3 的 AICore 架构代号（npu-arch 参数取值） |
| bisheng / hcc | AICore kernel 编译器 / AICPU kernel 交叉编译器 |
| reservedMap / allocatedMap | hybm 段登记表，地址分类（LOCAL/GLOBAL）依据（F18） |
| ASAN | AddressSanitizer，F20 的 UAF 仅在 ASAN 构建下检出 |
