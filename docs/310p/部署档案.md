# 310P AICPU kernel 部署档案

> **文档定位**：长寿命技术档案（10 年生命周期）。设计决策 D3 的实机验证沉淀
> （三堵墙完整论证见历史提交 cdc44c67）。
>
> **读者**：需要把 AICPU 编排 kernel 部署到 310P3 设备 CP1 的开发者与运维人员。

## 1. 当前部署流程

构建产物采用固定名称：`libmf_sdma_orch.so`、`libmf_sdma_orch.json`、
`libmf_sdma_orch_launch.json`。用户通过 `MF_SDMA_ORCH_JSON` 指定 launch JSON，
或者使用库的安装目录发现逻辑。

`smem_shm_create` 在 310P 选择 SDMA 后自动部署。初始化生成本次加载专用的临时
设备文件名，确认目标缺失后进行迁移、复制、校验和加载，CP1 根据独立名称加载代码。
运行时管理名称，无需手动维护 kernel 版本号。通道或部署失败会使建池返回错误。

## 2. 迁移、加载和清理

CUST 迁移使用 `cpuKernelMode=1`，将 SO 落到
`/home/CustAiCpuUser/lib/libmf_sdma_orch.so.*`。迁移 JSON 必须与 SO 基名一致。
库持有迁移句柄，并通过 Host 文件锁串行执行迁移和复制。

KFC 在设备 OS 中复制 SO 到
`/usr/lib64/aicpu_kernels/0/aicpu_kernels_device/`，检查入口字符串和文件大小。
库使用临时 launch JSON，以 `KFCKernel` 和 `cpuKernelMode=0` 加载该文件。

最后一个引用释放时，先停止 kernel，再删除本次创建的设备文件；其他进程的设备
文件保持原样。异常退出可能留下临时文件，后续启动使用新的加载名称。
诊断工具及回退方法见 `tools/aicpu_kernel_deploy/README.md`。

## 3. 部署约束

| # | 规则 | 依据 |
|---|---|---|
| 1 | 迁移和复制通过 Host 文件锁串行化；每次首次 Acquire 部署本次文件 | 同卡双 die 共享设备 OS 文件系统，跨卡独立（X9 实测） |
| 2 | deployer json 必须 `CUSTAICPUKernel`（mode=1 落真 ELF）；launch json **v9 起必须 `KFCKernel` + cpuMode=0**（type 5 免 28s monitor 计时，实机定案见平台事实 2026-10-08 条；v7 及之前为 `AICPUKernel`，受 28s 击杀约束） | json 类型决定 CANN 侧处理路径与设备侧计时分发 |
| 3 | 复制时使用运行时生成的独立名称 | CUST 临时文件需要串行复制；CP1 按文件名缓存加载结果 |
| 4 | 部署后检查入口字符串和精确文件大小 | 保证复制产物完整，释放引用后清理本次文件 |
| 5 | KFC 只发单条短命令；`sync=` 即命令退出码（0→sync=0，非零→507018） | 确定性失败重试不会过，判定看 sync=0 |
| 6 | NOTIFY 通道已证伪（不触发 + 流内 wait 挂死），通知链一律内存方案 | 机制档案第 1 节定论 5 |
| 7 | result/ovf buffer 必须 `ACL_MEM_MALLOC_HUGE_FIRST` | NORMAL_ONLY 落特殊段 SDMA 不可翻译 |

## 4. L0 OPP `.run` 的三堵墙与解锁条件（TODO-1）

产品终态（安装期部署）当前被推迟的根因，**全部实测**（xcclpp 包通道复现）：

| # | 墙 | 实测表现 |
|---|---|---|
| ① | 设备端 CMS 验签拒收无签名包 | `verifyFlag [Only Huawei]` |
| ② | 拒收**毒化宿主进程** | TsdOpen 失败 → `aclrtSetDevice` 507033——库形态不可接受的失败模式 |
| ③ | 解锁通道堵死 | `custom-op-secverify-enable` 开关容器内被拒需物理机；DCMI secverify 在 310P NOT_SUPPORT；user-certificate 需签发流程 |

**对照**：同为 OPP `.run` + AICPUKernel 的 `libcann_hybm_kernel.so` 在 A3 生产环境
工作——系 310P3 本机环境策略差异，非机制不可行。

**解锁条件（其一即可切 L0 并删自部署）**：拿到 user-certificate（官方第三方正解），
或目标环境验签开关可关闭。**通道侧无需改码**（包解压路径即 CP1 搜索路径）。

## 5. 部署回归

`test/integration/310p_aicpu_deploy/run.sh` 连续启动两组双 die 进程，检查每组首次
自动部署、D2D 数据校验及释放流程。诊断工具单独检查运行时文件存在、退出后文件缺失。
构建产物和设备侧路径的操作细节通过日志保留，测试结果存放在指定日志目录。

## 术语注释表

| 术语 | 说明 |
|---|---|
| CP1 | 控制处理器核，AICPU kernel 的执行环境 |
| deployer | 借 CANN `CUSTAICPUKernel`（mode=1）通道把 kernel ELF 落到设备用户目录的工具 |
| mini_kfc | 经 KFC 通道在设备内执行短命令的工具（此处用于复制 kernel 到 CP1 搜索路径） |
| KFC | 设备侧 shell 执行通道，`sync=` 字段承载命令退出码 |
| 验证门 | 部署后自检：目标文件存在（test -f）且导出符号可查（grep -q） |
| OPP `.run` | CANN 算子包安装格式，安装期解压到 vendors 目录，产品终态部署形态 |
| CMS | 设备端包管理/验签组件，拒收无签名包的墙①来源 |
| user-certificate | 华为签发的第三方算子证书，墙③的正解解锁路径 |
