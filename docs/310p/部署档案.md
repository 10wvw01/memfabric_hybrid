# 310P AICPU kernel 部署档案

> **文档定位**：长寿命技术档案（10 年生命周期）。设计决策 D3 的实机验证沉淀
> （三堵墙完整论证见历史提交 cdc44c67）。
>
> **读者**：需要把 AICPU 编排 kernel 部署到 310P3 设备 CP1 的开发者与运维人员。

## 1. 部署三段演进（D3 定案）

```
① P0 外部脚本（deployer + KFC）      ← 当前可用（本文第 2/3 节）
        │
② opt-in 自部署（MF_310P_AICPU_SELF_DEPLOY=1）   ← 过渡期（本文第 5 节）
        │
③ L0 OPP .run 安装期部署（产品终态）   ← 被三堵墙阻塞（本文第 4 节）
```

每段的生命周期语义：自部署文件与进程同生命周期（deployer 退出即触发清理链，天然
对齐池生命周期，消除外部脚本的保活时长错配问题——xcclpp 曾实测隔夜文件消失）。

## 2. 当前可用链：deployer + mini_kfc + 验证门

- **deployer**：以 `CUSTAICPUKernel`（mode=1）方式将 kernel ELF 迁移落
  `/home/CustAiCpuUser/`，该路径**不经验签**；
- **mini_kfc**：经 KFC 通道在设备内 `cat` 到 CP1 搜索路径
  `/usr/lib64/aicpu_kernels/0/aicpu_kernels_device/`；
- **验证门**：`test -f <目标文件>` + `grep -q <导出符号>`，正式运行前必跑
  （run 脚本内置 `ensure_deploy`，缺失自动重部署）。

**运维铁律（实测教训）**：deployer 保活到期退出会触发清理链**删除设备侧文件**
（P1 验收真实复现）——正式运行前必跑验证门。

## 3. 部署链运维规则七条（A.4，违反必踩）

| # | 规则 | 依据 |
|---|---|---|
| 1 | deployer 并发互斥作用域 = **卡**；部署粒度 = **每卡一次** | 同卡双 die 共享设备 OS 文件系统，跨卡独立（X9 实测） |
| 2 | deployer json 必须 `CUSTAICPUKernel`（mode=1 落真 ELF）；launch json 必须 `AICPUKernel` + cpuMode=0 | json 类型决定 CANN 侧处理路径 |
| 3 | 复制时改名；改 kernel 必 bump KVER | PID 后缀多版本拼接 = 损坏 ELF；CP1 按文件名 dlopen 缓存，不 bump 则加载旧缓存 |
| 4 | 正式验证前跑验证门（`test -f` + `grep -q <symbol>`） | deployer 清理链会删设备侧文件（第 2 节铁律） |
| 5 | KFC 只发单条短命令；`sync=` 即命令退出码（0→sync=0，非零→507018） | 确定性失败重试不会过，判定看 sync=0 |
| 6 | NOTIFY 通道已证伪（不触发 + 流内 wait 挂死），通知链一律内存方案 | 机制档案第 1 节定论 5 |
| 7 | result/ovf buffer 必须 `ACL_MEM_MALLOC_HUGE_FIRST` | NORMAL_ONLY 落特殊段 SDMA 不可翻译 |

## 4. L0 OPP `.run` 的三堵墙与解锁条件（TODO-1）

产品终态（安装期部署）当前被推迟的根因，**全部实测**（xcclpp 包通道复现）：

| # | 墙 | 实测表现 |
|---|---|---|
| ① | 设备端 CMS 验签拒收无签名包 | `verifyFlag [Only Huawei]` |
| ② | 拒收**毒化宿主进程** | TsdOpen 失败 → `aclrtSetDevice` 507033——库形态不可接受的失败模式 |
| ③ | 解锁通道堵死 | `custom-op-secverify-enable` 开关容器内被拒需物理机；DCMI secverify 在 310P NOT_SUPPORT；user-certificate 需签发流程 |

**对照**：同为 OPP `.run` + AICPUKernel 的 `libcann_hybm_kernel.so` 在 A3 生产环境
工作——系 310P3 本机环境策略差异，非机制不可行。

**解锁条件（其一即可切 L0 并删自部署）**：拿到 user-certificate（官方第三方正解），
或目标环境验签开关可关闭。**通道侧无需改码**（包解压路径即 CP1 搜索路径）。

## 5. 过渡期 opt-in 自部署设计（已设计未启用）

`MF_310P_AICPU_SELF_DEPLOY=1` 时在传输准备 Initialize 内完成部署，流程：

1. 验证门先查（已部署跳过；**同卡对端已部署即命中**，X9）；
2. 按**卡分组**抢 config store 分布式锁（`DistributedLockGuard` 现成设施；
   串行化粒度 = 卡：同卡互斥、跨卡文件系统独立可并行）；
3. mode=1 迁移 + KFC 复制 + 验证门 → mode=0 加载。

KFC（设备侧 shell 执行）进库代码需安全评审明示（opt-in + 全链日志）。

## 术语注释表

| 术语 | 说明 |
|---|---|
| CP1 | 控制处理器核，AICPU kernel 的执行环境 |
| deployer | 借 CANN `CUSTAICPUKernel`（mode=1）通道把 kernel ELF 落到设备用户目录的工具 |
| mini_kfc | 经 KFC 通道在设备内执行短命令的工具（此处用于复制 kernel 到 CP1 搜索路径） |
| KFC | 设备侧 shell 执行通道，`sync=` 字段承载命令退出码 |
| 验证门 | 部署后自检：目标文件存在（test -f）且导出符号可查（grep -q） |
| KVER | kernel 版本名（文件名一部分），CP1 按文件名 dlopen 缓存，改动必须提升 |
| OPP `.run` | CANN 算子包安装格式，安装期解压到 vendors 目录，产品终态部署形态 |
| CMS | 设备端包管理/验签组件，拒收无签名包的墙①来源 |
| user-certificate | 华为签发的第三方算子证书，墙③的正解解锁路径 |
| `DistributedLockGuard` | MemFabric 配置存储的分布式锁设施，自部署按卡分组互斥用 |
