# 310P 常驻消费设计档案 —— epoch 自限与监督续命

> **文档定位**：长寿命技术档案（10 年生命周期）。记载"池长存活"机制的设计思路与实现方式：
> AICPU 看门狗约束下，epoch 消费 kernel 如何以"看表下班、无缝换班"实现常驻。
> 实测数据口径见[平台事实](./平台事实.md)（watchdog/击杀级联勘正条），SQE 配方与
> 部署链见[机制档案](./机制档案.md)/[部署档案](./部署档案.md)；本文只讲生命周期设计。

## 1. 问题定义与硬约束（全部实机口径，2026-09-21）

310P 的设备发起 SDMA 依赖 AICPU 常驻消费：epoch kernel 轮询段尾保留区邮箱环，
把搬运请求转投 SQE。而平台对 AICPU 任务存在硬约束：

| # | 约束 | 实测依据 |
|---|---|---|
| C1 | **看门狗击杀边界 28~36s（板间漂移）**，超时 kernel 必被击杀 | 本机 35.9s（双 rank 一致，attr=60 惰性下同值）；现场口径 28s；探针口径 29~30s |
| C2 | **击杀终局为 hdc 断链**（`Hdc socket close`/`DEV_RUNNING_DOWN`/sync 507901），**进程级永久不可恢复** | 90 秒 launch 通道探针零恢复；"击杀后可恢复"仅对 KFC 通道成立，对 kernel launch 不成立 |
| C3 | **launch cfg 空属性被拒**（`numAttrs=0` → 107000 invalid value） | ex08v 实测，两轮复现 |
| C4 | **cntvct_el0 可用、各核独立计数**；cntfrq_el0 可读性无实机依据 | cntvct 为旧探针 kernel 实证原语；cntfrq 未验证（一次基于误诊的尝试已回退） |
| C5 | **节拍漂移**：空闲整循环实测 116~140µs/循环（100µs 退避 + 2×civac 游标读开销），随负载/环境变化 | 浸泡实测：同参数 epoch 相继出现 20.9s 与越界漂移 |

由此得出三条**设计公理**，全部方案取舍由它们推出：

1. **续命只能靠"从未被杀"**（C2：死后重启路径物理不存在）；
2. **自限必须用墙钟，不能用循环数换算时间**（C5：任何"次数×节拍"预算都会被漂移击穿）；
3. **超时 attr 只能作 API 占位，取值必须大于击杀边界**（C1+C3：小于边界的 attr 是引爆器，删又删不掉）。

## 2. 设计思路

### 2.1 换班模型（池长存活的形态）

"常驻"不等于一个 kernel 无限跑（C1 禁止），而是**无穷次有界轮转**：

```
epoch N 自限 18s 下班 → supervisor 同步到点 → 立即派 epoch N+1 → ……
                        └── 换班间隙邮件只延迟不丢失（环+游标语义）
```

环+游标语义是换班无损的前提：请求环与消费游标位于段尾保留区，epoch 退出不销毁；
下一纪从游标处继续消费，被杀/换班瞬间的在途邮件至多重放一次（memcpy 幂等）。

### 2.2 三层防线

| 层 | 机制 | 解决什么 |
|---|---|---|
| **主限** | kernel 墙钟自限 `EPOCH_WALL_S = 18s`（cntvct_el0 纪内差值） | 忙/闲、节拍漂移多少，epoch 墙钟恒定——C5 免疫 |
| **兜底** | 循环上限 `EPOCH_MAX_LOOPS = 150000`（≈21s @140µs） | 计时器失效（C4 返回 0）时退化为纯循环数退路，仍在边界内 |
| **纵深** | 监督分类续命（健康被杀不计数、立即重派） | 理论上主限下不应触发；若未来固件击杀可恢复则自动生效；同时防真错误误判弃疗 |

### 2.3 时间预算与约束链

```
18s（墙钟主限）< 28s（板间最紧击杀边界 C1）
```

裕量 ≥10s 且**与负载无关**——这是墙钟方案的本质优点：循环数方案的裕量随节拍
漂移缩水（历史事故：220000 循环名义 22s 实跑 28.6s；180000 版第 5 纪漂到 ~140µs
再度越界），墙钟方案的裕量是常量。换班间隙约百毫秒级（含 20ms 频率标定），
占空比损耗 <2%，epoch 轮转 ~3.3 次/分钟。

### 2.4 被否决的备选方案（含否决理由）

| 备选 | 否决理由 |
|---|---|
| 循环数预算（次数×节拍计价） | 节拍漂移击穿（C5，两代版本实测翻车） |
| attr 25s 作"温和上界"（原设计） | attr 到期与设备击杀同样以 hdc 断链收场（C1/C2），不是温和路径 |
| 删除 attr | numAttrs=0 被 runtime 拒绝（C3） |
| 读 cntfrq_el0 拿频率 | 可读性无实机依据（C4），曾按误诊尝试即回退 |
| 击杀后重启续命 | 会话永久死亡（C2），物理不可行；仅保留为纵深防御 |
| kernel 内 wall 频率跨纪缓存 | cntvct 各核独立计数（C4），跨核时间戳不可比；每纪 20ms 标定代价可忽略 |

## 3. 实现方式

### 3.1 契约常量（`src/hybm/ops/hybm_kernel/hybm_sdma_contract.h`）

| 常量 | 值 | 语义 |
|---|---|---|
| `HYBM_SDMA_ORCH_KVER` | 9 | 设备侧产物版本号（文件名缓存刷新，见 3.4） |
| `HYBM_SDMA_ORCH_EPOCH_IDLE_US` | 100 | 空闲退避（实测整循环 ~116-140µs，勿按此值换算预算——见 2.4 第一条） |
| `HYBM_SDMA_ORCH_EPOCH_WALL_S` | 18 | **epoch 墙钟主限**（秒） |
| `HYBM_SDMA_ORCH_EPOCH_MAX_LOOPS` | 150000 | 循环上限兜底（时钟失效时 ≈21s） |

host 侧配套（`hybm_sdma_orchestrator.cpp`）：`EPOCH_ATTR_TIMEOUT_S = 60`（attr 占位，
须 > 击杀边界）；`LAUNCH_TIMEOUT_S = 25` 仅用于 KFC 命令（毫秒级命令，不触级联）。

### 3.2 kernel 侧（`src/hybm/ops/hybm_kernel/hybm_sdma_orch_kernel.cc`）

**计时原语**——只依赖实机验证过的 cntvct_el0，各核独立计数故只做纪内差值：

```cpp
inline uint64_t readCntvct()   // mrs cntvct_el0（旧探针 kernel 实证原语）
{
    uint64_t v;
    __asm__ __volatile__("mrs %0, cntvct_el0" : "=r"(v));
    return v;
}
```

**频率标定**——usleep 下界反推，安全方向可证：睡眠只会长不会短 →
标定值 ≤ 真值 → 墙钟只会提前触发（epoch 变短无害，变长致命）：

```cpp
inline uint64_t calibCntFreq()
{
    const uint64_t t0 = readCntvct();
    usleep(20000);                            // ≥20ms（下界）
    return (readCntvct() - t0) * 50ULL;       // ticks/20ms × 50 = ticks/s
}   // 返回 0 = 计数器不走 → 上层退化纯循环上限
```

**入口**——校准 + 戴表 + 结果头刷出（被杀后 host 可辨"健康启动未及退出"）：

```cpp
result->magic = HYBM_SDMA_ORCH_RESULT_MAGIC;   // …四个字段初始化…
finishResult(result);                          // 入口即刷出（cvac+dsb）
const uint64_t cntFreq = calibCntFreq();       // 20ms 标定
const uint64_t wallDeadline =
    (cntFreq != 0) ? readCntvct() + cntFreq * HYBM_SDMA_ORCH_EPOCH_WALL_S : 0;
```

**消费循环**——每 64 次迭代抽查一次墙钟（mrs 开销 ~ns，抽查粒度毫秒级足够）：

```cpp
for (uint32_t loops = 0; loops < HYBM_SDMA_ORCH_EPOCH_MAX_LOOPS; loops++) {
    if ((loops & 63U) == 0 && wallDeadline != 0 && readCntvct() >= wallDeadline) {
        break;    // 墙钟到期：exitReason 保持 DEADLINE，干净返回，host 续命
    }
    /* …停止标志检查 / 环轮询 / 邮件消费（原逻辑不变）… */
}
```

### 3.3 host 侧（`src/hybm/csrc/entity/hybm_sdma_orchestrator.cpp`）

**SupervisorLoop 验尸分类**——sync 失败先 D2H 读结果区，按"有无错误记录"分诊：

```cpp
if (r.magic == HYBM_SDMA_ORCH_RESULT_MAGIC && r.mainRet == 0 &&
    r.exitReason != HYBM_SDMA_ORCH_EXIT_ERROR) {
    /* 无错误记录的死亡 = 击杀健康纪：环+游标无损，不计放弃计数直接续命 */
    BM_LOG_WARN("epoch watchdog-killed (healthy, relaunch), ...");
    continue;
}
/* 真错误（13xx/1360 等已写入结果区）→ ERROR 日志 + errors++ */
if (++errors > 16) {   /* 连续 16 次放弃（带 ERROR 日志与 sqId/devId） */ }
```

计数语义：`errors` 只在**干净自退**（sync 成功）时清零。主限正常工作时每纪
干净自退、计数恒零；分类分支是纵深防御（本平台击杀后会话即死，实际到不了
重派那一步——保留给未来固件变化）。

**launch attr 占位**——不能删（C3）只能调大（公理 3）：

```cpp
constexpr uint32_t HYBM_SDMA_ORCH_EPOCH_ATTR_TIMEOUT_S = 60;  /* > 击杀边界 28~36s */
```

**停止路径**——`StopSupervisor` 写设备停止标志 → kernel 一轮轮询（~130µs）内净退；
销毁窗口内段先销毁导致 kernel 读段被杀，为预期自愈（INFO 级日志，下一纪净退）。

### 3.4 部署联动（修复生效的最后一环）

- **KVER 文件名版本机制**：设备侧产物 `libmf_sdma_orch_v${KVER}.so/.json`，CP1 按文件名
  dlopen 缓存、同名不重载 → **kernel 任何变更必须 bump KVER**，否则已部署设备继续跑旧件
  （部署闸门 `test -f` 命中旧名即跳过部署，修复静默失效）。
- **CMake 从契约头解析 KVER**（`hybm_kernel/CMakeLists.txt`）：`file(STRINGS)` 提取
  `HYBM_SDMA_ORCH_KVER` + `CMAKE_CONFIGURE_DEPENDS` 头变更触发重配置。勿改回缓存变量
  ——旧 build 目录缓存的版本号会把新 kernel 配到旧名下。
- **自动部署链**：闸门探测缺失 → CUST 迁移落盘 → `cat` 复制到 CP1 搜索路径 →
  入口符号 + 精确尺寸校验（详见[部署档案](./部署档案.md)）。

### 3.5 诊断日志速查

| 日志关键字 | 级别 | 含义 | 处置 |
|---|---|---|---|
| `epoch watchdog-killed (healthy, relaunch)` | WARN | epoch 被杀但无错误记录 | 主限 18s 下不应出现；出现即说明墙钟失效（标定/寄存器异常）或边界收紧，抓结果区与 slog 复盘 |
| `epoch sync failed ... mainRet=... exitReason=2` | ERROR | kernel 错误退出（活查询 13xx / SQ 满 1360 / 敲铃 1390） | 按 mainRet 错误码定位，见机制档案错误码表 |
| `epoch launch failed 16 times, supervisor exit` | ERROR | 连续 16 次启动失败，监督永久放弃 | 检查设备会话状态与部署完整性；池需重建 |
| `epoch faulted during shutdown` | INFO | 销毁窗口内段先销毁的预期自愈 | 无需处置 |

## 4. 验证口径与结果（2026-09-21，Atlas 300I Duo 实机）

| 相位 | 判据 | 结果 |
|---|---|---|
| 部署+功能 | 新版本名自动部署、双 rank 流水逐字校验 | PASS（v9 自动部署，mismatch=0） |
| **空闲浸泡 11 分钟**（每 30s 跨纪边界全量校验 ×23 轮） | 零击杀零告警、全部 mismatch=0 | **PASS**：23/23，零 epoch 事件（修复前同场景 120s 必死） |
| **满载浸泡 62s**（背靠背 12001 轮、9.6 万封邮件） | 同上 | **PASS**：全部 mismatch=0，零 epoch 事件——忙时墙钟免疫实证 |
| 对照组（超预算 kernel，故意不下班） | 应在 35.9s 准点被杀且会话永久死亡 | 符合预期——反向证明"从未被杀"是唯一活路 |

验收纪律：**单轮功能通过不代表不死**——必须含跨多个纪边界（≥3×18s）的浸泡，
且浸泡期日志零 `watchdog-killed`/`launch failed` 事件。

## 5. 防回归清单（历史教训，勿再犯）

1. **勿按"退避时长×次数"计价 epoch 预算**——漏算循环开销与节拍漂移，两代版本实测翻车；
2. **勿给 epoch 设小于击杀边界的 attr**——attr 到期以 hdc 断链收场，不是温和上界；
3. **勿用 numAttrs=0 的空 cfg**——runtime 拒绝（107000）；
4. **勿跨核比较 cntvct**——各核独立计数，墙钟只用纪内差值；
5. **勿依赖 cntfrq_el0**——可读性无实机依据，频率用 usleep 下界标定；
6. **改 kernel 必须 bump KVER**，并确认 CMake 从契约头解析生效（防缓存陈旧）；
7. **击杀后恢复类逻辑只能作纵深防御**——本平台击杀即进程级死刑，主防线永远是"不越界"。
