# MemFabric 310P 使用指南（Atlas 300I Duo）

本手册面向在 Atlas 300I Duo（Ascend310P3）上使用 MemFabric 的用户，覆盖从环境准备到跑通全部 310P 示例的完整流程。假设读者会用 Linux 命令行、有 C++ 或 Python 基础，没有读过本仓库代码。

310P 的深入技术背景（机制原理、部署链路、平台实测事实）不在本手册展开，见[第 8 节](#8-遇到问题怎么办)的资料索引。

## 1. 310P 上能做什么

Atlas 300I Duo 是单卡双 die 的推理卡，两个 die（dev0/dev1）各自有 HBM 显存。MemFabric 在这张卡上提供两类能力，对应两套接口：

| 能力 | 接口 | 说明 | 对应示例 |
|------|------|------|---------|
| 双 die 内存池 | BM API | 单卡 2-rank 组池：HBM 池 + DRAM 池，host 侧发起拷贝，支持 H2G/G2H/G2G/H2GH/GH2H 五个方向 | 07 示例 |
| 设备发起搬运 | SHM API | AICore kernel 里直接发搬运请求（signal），AICPU 上的搬运 kernel 循环执行 SDMA 搬运（每 15 秒一轮换班，间隙约 0.1 秒、数据零丢失），对端 AICore 等待收件（wait）。host 不参与数据搬运 | 08 示例 |

使用边界：

- 本手册范围是**单卡双 die 2-rank**。跨机、多卡更大规模在 310P 上未验证（4-rank/8-rank 见根目录方案文档，属设计稿）。
- 与 A2/A3 平台的差异：310P 的 HBM 池走 ACL VMM 链路（`aclrtMallocPhysical` + shareable handle 导入导出），不是 A3 的 STARS SQE 路径；设备间拷贝由 `aclrtMemcpyAsync` D2D 承担。

## 2. 环境准备

| 项 | 要求 |
|----|------|
| 硬件 | Atlas 300I Duo（Ascend310P3） |
| CANN | ≥ 9.1（驱动 Innerversion V100R001C10 及以上） |
| 编译器 | GCC ≥ 11.4 |
| CMake | ≥ 3.12（推荐 3.20+） |
| Python（可选） | ≥ 3.8，跑 07 Python 版还需 torch |

跑 08 示例额外需要：

- **MPI**：双 rank 拉起用。编译与启动必须用同一套（混用会段错误）。两套任选：发行版（`/usr/bin/mpirun` + `/usr/lib/aarch64-linux-gnu/openmpi/`，编译加 `-DOMPI_SKIP_MPICXX`）或自装（`/usr/local/openmpi` 全套）。
- **bisheng 编译器**：CANN 工具链自带（`$ASCEND_HOME_PATH/bin/bisheng`），编译 08 示例的 AICore 代码用。

确认环境：

```bash
npu-smi info          # 能看到 310P3 设备且 Health 为 OK
echo $ASCEND_HOME_PATH  # 应指向 CANN 安装根，如 /usr/local/Ascend/cann-9.1.0
```

## 3. 安装

### 3.1 Python（pip）

```bash
pip install memfabric_hybrid          # 在线
pip install --no-index memfabric_hybrid-*.whl   # 离线（先下载对应架构的 whl）
```

### 3.2 C API（源码编译）

方式一，一键脚本（产出 `.run` 安装包，默认 `XPU_TYPE=NPU`）：

```bash
bash script/build_and_pack_run.sh
bash output/memfabric_hybrid-*.run    # 安装到 /usr/local/
source /usr/local/memfabric_hybrid/set_env.sh
```

方式二，直接 cmake（08 示例的 `run.sh` 用的就是这套，产出静态库和 kernel 产物在 `build/` 下）：

```bash
cmake -B build -DXPU_TYPE=NPU -DBUILD_PYTHON=OFF && cmake --build build -j
```

完整参数说明见[编译安装文档](../installation.md)。

### 3.3 协同 kernel 部署：不需要手工操作

08 示例依赖的设备侧搬运 kernel（`libmf_sdma_orch.so` + launch json，版本号随演进递增）由主构建自动产出。**建池时库会自动完成部署**：设备侧缺失时自动迁移落盘、就位搜索路径、校验符号和尺寸。全新设备或全新环境没有手工部署步骤。

需要手动部署或排查部署链路时，见 `tools/aicpu_kernel_deploy/`（诊断用）。

## 4. 快速验证

两个示例都自带进程间组网（07 内嵌配置存储，08 用 MPI 会合），不需要额外起任何服务。

### 4.1 示例 07：双 die 双池（BM API）

Python 版（需已安装 wheel 和 torch）：

```bash
cd examples/memory_pool/01_basic/07_310p_die_pair_pool
python3 07_310p_die_pair_pool.py
# 期望输出: 07_310p_die_pair_pool ok
```

C++ 版（先按 3.2 方式一构建；**以下命令须在仓库根目录执行**——`-Isrc/...` 等相对路径以仓库根为基准，在示例目录内执行会报 `smem.h: No such file`）：

```bash
CANN=/usr/local/Ascend/cann-9.1.0
g++ -std=c++17 -w -o /tmp/p5_e2e 07_310p_die_pair_pool.cpp \
  -Wl,--start-group \
  build/src/smem/csrc/libmf_smem.a \
  build/src/hybm/csrc/libmf_hybm_core.a \
  build/src/acc_links/csrc/libacc_tcp_net.a \
  -Wl,--end-group \
  -Isrc/hybm/include -Isrc/smem/include/host -Isrc/hybm/csrc/transport \
  -Isrc/hybm/csrc -Isrc/hybm/csrc/common -Isrc/hybm/csrc/under_api -Isrc/hybm/csrc/entity \
  -Isrc/hybm/csrc/mm -Isrc/hybm/csrc/driver -Isrc/hybm/csrc/driver/userspace \
  -Isrc/hybm/csrc/driver/version -Isrc/hybm/csrc/ts_engine -Isrc/util/csrc \
  -pthread -ldl
export ASCEND_HOME_PATH=$CANN
export LD_LIBRARY_PATH=$CANN/aarch64-linux/lib64:/usr/local/Ascend/driver/lib64/driver:/usr/local/Ascend/driver/lib64/common
/tmp/p5_e2e 0 & /tmp/p5_e2e 1 & wait
# 期望输出: 双方 === P5 rN DONE ===
```

验收口径（8MB 逐字校验，mismatch 必须为 0）：PhaseA 跨 die 写读、PhaseB G2G 跨 die 拷贝、PhaseC DRAM 池跨 rank 读写，详见[示例 README](../../examples/memory_pool/01_basic/07_310p_die_pair_pool/README.md)。

### 4.2 示例 08：设备发起 SDMA 协同（SHM API）

一键运行（自动完成环境自检、构建检查、编译、双 rank 拉起）：

```bash
cd examples/memory_pool/01_basic/08_310p_aicore_aicpu_sdma
bash run.sh
# 期望输出: 双方 === EX08 rN PASS ===，r0 输出流水对串行的加速比
```

脚本会自动定位版本号最高的 launch json，无需手工指定。分步命令和原理见[示例 README](../../examples/memory_pool/01_basic/08_310p_aicore_aicpu_sdma/README.md)。

示例内含四段验收：

1. 多块流水搬运，1MB 数据逐字校验（mismatch=0 为通过）；
2. 串行对照，输出流水对串行的加速比（实机 1.6~2.0x 量级）；
3. 全设备同步共存探针：模拟深度学习框架分配器内部的设备同步，验证搬运 kernel 不阻塞它（等待时间 = 当前轮班残余，应少于 15 秒）；
4. 长稳测试（可选）：持续收发压测，跨轮班边界验证零丢失：

```bash
# 长稳压测(换轮无缝性验证, 原 08 ③)已迁测试目录:
cd test/integration/310p_sdma_stability && STRESS_ROUNDS=30000 bash run.sh   # 约 46 秒，期望 ①长稳 ②设备同步 PASS（跨 ≥3 次轮班，单轮最大时延 <10ms）
```

### 4.3 跑完清理

正常退出不需要清理。**异常退出**（kill、段错误）会在 `/dev/shm` 残留共享内存段文件，占满该目录（默认 64MB）会导致 DRAM 池创建失败，并连带 HBM 窗口基址漂移。清理后重跑：

```bash
rm -f /dev/shm/memfabric_hybrid_*
```

| 路线 | 入口资料 | 参考代码 |

## 6. 环境变量

310P 相关的变量（完整列表见[环境变量文档](../environment_variables.md)）：

| 变量 | 默认 | 作用 |
|------|------|------|
| `MF_CONFIG_STORE_URL` | 无 | BM API 跨进程组网必填（`tcp://`、`etcd://` 或 `reg://`）。07 示例内嵌本地存储可跳过；SHM 同卡协同模式不需要 |
| `MF_SDMA_ORCH_JSON` | 自动发现 | 协同 kernel 的 launch json 路径。未设置时依次找：安装前缀、当前目录 |
| `MF_SDMA_ORCH_EPOCH_BUDGET_S` | 15 | 搬运 kernel 每轮时长（秒）。一般无需调整；永不退出模式（4294967295）仅供诊断，会阻塞框架内部的设备同步 |
| `MF_SDMA_ORCH_DISABLE` | 空（启用） | 设为 `1` 或 `on` 显式禁用协同模式（诊断用），此时 `smem_shm_sdma_get_workspace` 返回 NULL |
| `MF_LOG_LEVEL` | 无 | 日志级别 0-4（DEBUG 到 OFF），仅 Python 接口生效 |

## 7. 已知限制

- **规模**：world_size=2 固定（单卡 die 对映射 dev0/dev1）。
- **协同搬运规格**：单次搬运 ≤ 1MB；长度须 4 字节对齐；请求环深 64（满环时 signal 自旋背压）；到达环深 1024（消费不及时溢出会显式报错）；每 rank 段末尾 48KB 为邮箱保留区，由 MemFabric 托管，不能存放用户数据。
- **池规格**：HBM 池 ≤ 64GB/rank；DRAM 池建议 ≥ 2MB 对齐。
- **跨机路径**：未在 310P 验证。

## 8. 遇到问题怎么办

1. 先开日志定位（`MF_LOG_LEVEL`，Python 接口）；
2. 按问题类型查档案：
   - 程序跑挂、行为与预期不符 → [平台事实](./平台事实.md)：这块板子实测是什么行为（F/S/T 三张表），含工具链坑；
   - kernel 部署相关 → [部署档案](./部署档案.md)：kernel 上设备的链路与运维铁律；
   - 写 kernel、想理解搬运指令怎么构造 → [机制档案](./机制档案.md)；
3. 通用 FAQ 见 [Wiki](https://gitcode.com/Ascend/memfabric_hybrid/wiki/FAQ.md)；
4. 常见坑：异常退出后 `/dev/shm` 残留（见 4.3）。
